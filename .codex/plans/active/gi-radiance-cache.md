# GI: 복셀 트레이스 + 프로브 래디언스 캐시

## 목표와 범위

- 동적 전역 조명(간접 확산광, 무한 바운스, 스카이/에미시브 기여)을 WebGPU에서 제공한다. 정적 베이크가 아니라 건물 편집 결과를 변경마다 반영한다.
- source of truth는 그대로 building 스토어다. GI의 복셀 볼륨과 프로브는 그 위의 파생 projection이며 저장·네트워크 대상이 아니다(INV-002, INV-005). 저장 형식과 network 계약은 바꾸지 않는다.
- 근거: 월드는 4m 격자, 1m 높이 단계, 벽 두께 0.5m의 축 정렬 박스라 타일·벽·블록 AABB를 복셀 점유로 직접 변환할 수 있다. SDF 생성과 서피스 캐시 없이 복셀 DDA로 정확한 레이 트레이스가 가능하다.
- 알고리즘: 복셀 점유 볼륨(재질 팔레트 포함)에 3D DDA로 프로브 레이를 쏜다. 프로브마다 6방향 조도 큐브(ambient cube)를 저장하고, 히트 지점 셰이딩에 이전 프레임 프로브 값과 직사광(그림자 레이 포함)을 사용해 다중 바운스를 얻는다.
  - 조도 큐브는 표면 대부분이 축 정렬인 이 프로젝트에서 축 방향 법선의 오차가 0이고 음수 로브와 링잉이 구조적으로 없다.
  - 2단계 캐스케이드: 성긴 레벨(간격 2m)에 촘촘한 레벨(간격 1m)을 `fineBounds` 영역에 얹고 경계에서 섞는다. 히트 지점 되먹임도 두 레벨을 같은 식으로 읽는다.
  - 프로브 재배치: 격자점이 복셀 안(표면 경계 포함)이면 축 방향으로 가장 가까운 빈 곳으로 추적 원점만 옮긴다. 같은 축 양쪽이 동시에 비는 얇은 벽 한가운데는 무효로 둔다. 조회는 격자 위치 그대로라 셰이더와 어긋나지 않는다.
  - 적응형 blend: 새 추정의 전체 조도가 저장값과 크게 다르면(변화량 0.25~0.7 구간을 smoothstep) blend를 1 쪽으로 올린다. 정상 상태 잡음의 99%(변화량 0.19)에는 반응하지 않는다.
- 수치 안정성: 알베도 상한 0.95와 방사휘도 상한으로 되먹임 이득이 항상 1 미만이고, NaN/무한대는 환경·재질·레이 단계에서 걸러 프로브 값이 오염되지 않는다.
- 프로브 갱신: 스케줄링(더러운 프로브 큐, 순환 커서)은 JS, 갱신 계산은 `public/wasm/gaesup_gi.wasm` 커널(`src/core/gi/wasm`, Rust)이 한다. 캐스케이드마다 인스턴스 하나를 두고 모든 버퍼를 생성 시점에 할당하므로 메모리가 늘지 않는다. wasm을 받지 못하면 같은 결과를 내는 JS 경로를 쓴다. canonical 구현은 TS(`gi/core`)이며 WASM은 그 포팅이고 패리티 테스트로 묶는다.
- WebGL fallback은 GI 없음(기존 ambient)이다. 셰이더 모듈은 동적 import로만 로드한다(INV-016, INV-017).

## slice

1. `src/core/gi/core/` 순수 수학 코어(복셀 그리드, DDA, 샘플링, 조도 큐브, 프로브 볼륨, 캐스케이드, 복셀 장면). 완료.
2. building 상태를 복셀 박스로 변환(`gi/utils`), `GiVolume` 컴포넌트, TSL 조도 노드(`rendering/tsl/gi.ts`), 공개 API, `examples/pages/GiPage`. 코드 작성과 타입·셰이더 생성 검증 완료, 브라우저 미검증.
3. 프로브 갱신 WASM 커널. 완료(패리티·성능 측정).
4. 후속: 메인 월드 Canvas의 WebGPU 전환 후 building 머티리얼에 연결, 워커 병렬화 또는 GPU 컴퓨트 이관, 가시성(Chebyshev) 가중, 카메라 추종 촘촘한 레벨, 작은 발광체의 직접광 처리, 동적 캐릭터 복셀화.
5. 워커 이관(완료): 추적·아틀라스 패킹을 인라인 Web Worker(`gi/worker`)로 옮기고, 수렴하면 갱신을 4분의 1로 줄이며(`probeSchedule.ts`), 셰이더 샘플을 픽셀당 12번에서 3번으로 줄였다. 메인 스레드 GI 비용이 예제 섬에서 초당 140~190ms에서 0.3ms가 됐다.

## 제외

- 메인 월드 Canvas의 WebGPU 전환은 renderer-modernization plan이 소유한다. GI는 예제 페이지의 자체 WebGPU Canvas에서 먼저 동작한다.
- 라이브러리 소비자는 `gaesup_gi.wasm`을 `wasm/` 경로에 직접 호스팅해야 한다(기존 `gaesup_grass_attr.wasm`과 같은 제약). 없으면 JS 경로로 동작한다.
- 실험했지만 채택하지 않은 것: 접촉 AO 탭 보정, SH deringing과 지수 로브 복원(모두 정답 대비 오차가 줄지 않음), 프로브 간격 1m 균일 격자(비용 대비 캐스케이드보다 못함), 표면 근처 프로브 재배치(영향 없음), 되먹임 뒤쪽 감쇠 강도 조정(재배치 뒤 차이 없음).
- 리스크: 실제 GPU 실행과 화면은 브라우저 실측 전까지 확인되지 않았다. 램프 같은 작은 발광체의 근거리 조명(프로브 간격보다 짧은 범위)은 원리적으로 잡지 못한다.

## 검증

- Node 타입 스트리핑 러너에서 `src/core/gi` 테스트 83개 통과.
  - DDA는 랜덤 레이 3000개를 레이 마칭과 대조하고 변이 주입 시 실패를 확인했다.
  - 밀폐된 방의 다중 바운스가 해석해 e/(1-albedo)에 수렴하고, 캐스케이드도 같은 값으로 수렴한다.
  - WASM 패리티: 같은 장면을 JS와 WASM으로 갱신해 상대 차이 1e-5 이내(실측 0, 비트 일치). 의미 있는 변이(되먹임 감쇠 하한, 적응 임계값)를 넣은 바이너리는 0.013~0.03 차이로 실패함을 확인했다.
- 타입: 스크래치패드에 three 0.185.1, @types/three 0.185.4, TypeScript 6.0.3, React 19, R3F 9.7, drei 10.7.8을 설치해 저장소 tsconfig의 엄격 옵션으로 GI 소스, 컴포넌트, 테스트, 예제 페이지를 검사했다. 통과. 이 과정에서 `emissiveNode.add` 타입 오류를 찾아 `materialEmissive` 기반으로 고쳤다(발광 재질도 기존 발광을 유지한다).
- 셰이더: `scripts/verify-toon-water-nodes.mjs`와 같은 헤드리스 빌더로 GI 노드를 WGSL(7403B)과 GLSL(8811B)로 생성, 텍스처 샘플 12개. 생성된 WGSL의 좌표·면 선택·가중치·캐스케이드 식이 CPU 모델과 같음을 확인했다.
- 정답 대비 오차(예제 씬, 경로추적 깊이 24를 정답으로, 36개 표면점, 휘도). GPU 경로는 셰이더와 같은 half-float 반올림 + clamp-to-edge 하드웨어 삼선형 보간 시뮬레이션이다.

  | 구성 | 경로 | RMS 상대오차 | 로그 오차 | 평균 편향 | 정상상태 떨림 |
  |---|---|---|---|---|---|
  | 초기 L1 SH, 간격 2m | CPU | 0.472 | 0.273 | +0.173 | 4.9% |
  | 조도 큐브 + 캐스케이드 | CPU | 0.321 | 0.135 | -0.018 | 3.1% |
  | 조도 큐브 + 캐스케이드 | GPU | 0.356 | 0.161 | +0.062 | 3.1% |
  | + 프로브 재배치 | GPU | 0.297 | 0.128 | -0.016 | 3.2% |
  | + 적응형 blend | GPU | 0.297 | 0.131 | -0.007 | 2.5% |

  남은 가장 큰 오차는 램프 0.5m 옆 점(정답의 0.36배)이다.
- 성능(Node, 예제 씬 프로브 4180개, 레이 64): 프레임당 32개 JS 1.37ms -> WASM 0.82ms, 128개 5.58ms -> 3.23ms(1.7배). 레이당 평균 DDA 26단계. 브라우저 실측은 아니다.
- 실행하지 못한 것: 저장소 환경의 jest, eslint, 브라우저. 다음을 실행해야 한다.
  - `pnpm test -- src/core/gi src/__tests__/publicApi.test.ts examples/config --runInBand`
  - `pnpm exec tsc -p tsconfig.build.json --noEmit`
  - 변경 파일 eslint, `/gi` 라우트 브라우저 확인(WebGPU, wasm 로드 여부)
- wasm 재빌드: `bash src/core/gi/wasm/build.sh`(Rust와 wasm32-unknown-unknown 타깃 필요).
