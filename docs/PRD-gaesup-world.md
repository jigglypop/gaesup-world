# gaesup-world 제품 요구사항

작성일: 2026-09-22 · 기준: 1.0.32 소스 및 이번 미니홈피 변경 · 상태: 코드 기반 PRD

## 1. 제품 목표

React 앱에서 캐릭터가 움직이고, 사용자가 공간을 편집하고, 저장한 세계를 다시 열거나 다른 사람과 방문할 수 있는 웹 3D 라이브러리를 제공한다. 미니홈피는 라이브러리의 실제 사용 예제이자 편집·저장·렌더링 회귀를 확인하는 공개 제품이다.

핵심 목표는 **기능을 유지하면서 프레임 비용, 초기 로딩, 편집 지연, 수명 종료 후 남는 작업을 줄이는 것**이다. 성능 개선은 동일 장면·장치·백엔드의 전후 측정으로 판정한다. 구현 존재, 단위 테스트, 실제 브라우저 실행, 운영 배포는 별도 증거로 관리한다.

## 2. 사용자와 주요 여정

| 사용자 | 필요한 결과 | 완료 조건 |
| --- | --- | --- |
| 라이브러리 소비 개발자 | 기존 React 앱에 월드·캐릭터·편집기 추가 | 공개 엔트리로 import, 타입 검사와 실제 렌더 성공 |
| 공간 제작자 | 타일·높이·계단·가구를 편집하고 보존 | 편집→실행 취소/다시 실행→저장→새로고침 복원 |
| 방문자 | 데스크톱·모바일에서 공간 탐색 | 클릭/키보드 이동, 카메라 조작, 오류 시 복구 |
| 함께 방문하는 사용자 | 동일 방의 참가자·채팅·공간 변경 확인 | 실제 방 서버 연결, 권한·방 격리·퇴장 복원 |
| 엔진 기여자 | 병목 재현과 변경 효과 확인 | 소스 식별자·측정 조건·원본 결과가 연결된 비교 |

## 3. 코드 범위와 현재 구조

전체 모듈 정적 목록은 [코드 인벤토리](./PRD-code-inventory.md)에 기록한다. 공개 엔트리, 핵심 소유권·저장 경로, 미니홈피 구현, 테스트, 배포 스크립트를 직접 검토했다. 인벤토리 생성은 모든 파일의 수동 정밀 감사나 모든 장치의 실행 검증을 의미하지 않는다.

| 영역 | 현재 코드와 역할 | 제품 요구사항 |

| 월드 런타임 | `core/runtime`, `world`, `boilerplate`, `stores`, `simulation` | 월드별 상태·서비스 소유, 명시적인 시작/정지/해제 |
| 캐릭터·입력 | `character`, `motions`, `animation`, `input`, `camera` | 입력 소유권, 접지·충돌·카메라·애니메이션 일관성 |
| 공간 질의 | `navigation`, `interactions`, `grid`, `placement` | 실제 장애물·높이를 반영한 이동과 선택 |
| 건축·자연 렌더링 | `building`, `rendering`, `weather`, `effects`, `perf` | WebGPU 우선, WebGL2 대체 경로, 인스턴싱·컬링·자원 정리 |
| 씬 편집 | `scene-object`, `scene`, `editor`, `prefab`, `project-settings` | 안정 ID, 명령 기반 편집, 계층 변환, 문서 저장·교환 |
| 에셋·아바타 | `assets`, `character`, `src/avatar.ts`, `scripts/assets` | 로딩/오류/해제 상태, 재사용 캐시, 조립형 아바타 |
| 게임 도메인 | `items`, `inventory`, `economy`, `catalog`, `crafting`, `farming`, `town` | 도메인 상태와 명령을 플러그인·저장 계약에 연결 |
| 사회·진행 | `dialog`, `quests`, `relations`, `mail`, `events`, `gameplay` | 진행 상태 보존, 중복 이벤트와 월드 간 상태 간섭 방지 |
| 시간·오디오 | `time`, `audio`, `tools` | 일시 정지·재개·종료에 맞춘 업데이트와 재생 수명 |
| 저장·확장 | `save`, `plugins`, `platform`, `content`, `i18n` | 버전 마이그레이션, 검증·복구, 확장 등록과 해제 |
| NPC·네트워크 | `npc`, `networks`, `server-contracts.ts` | 정책 요청 수명, 관측·응답 소유권, 권위·재접속 계약 |
| 다음 런타임 | `src/next` | 엔티티 세대, TransformStore, TaskGraph/RenderGraph, GPU 인스턴스 경로 |
| 블루프린트 | `src/blueprints` | 캐릭터·차량 등 정의를 컴포넌트와 생성 흐름으로 변환 |
| Unity 연동 | `scene-object/unity`, `integrations/unity` | JSON 씬 교환, 안정 ID·계층·변환·컴포넌트 호환 |
| 예제·검증 | `examples/minihome`, `engine`, `performance`, `scripts/probe-*` | 일반 사용자 화면과 엔진/성능 재현 화면의 목적 분리 |

지원 선언은 React 18/19, R3F 8/9, Drei 9/10, Rapier 1/2 및 `package.json`의 Three peer 범위를 따른다. 지원 선언 전체 조합의 검증 완료를 현재 설치 환경 테스트와 혼동하지 않는다. `src/next`의 존재를 기존 런타임 전체 이전 완료로 해석하지 않는다.

## 4. 기능 요구사항

우선순위: P0는 배포와 데이터 보존의 필수 조건, P1은 핵심 제품 품질, P2는 후속 확장이다. 아래의 구현 상태는 코드 확인 기준이며 이번 실행 결과는 배포 기록에 별도 남긴다.

| ID | 우선순위 | 요구사항 | 현재 상태·근거 | 수용 기준 |
| --- | --- | --- | --- | --- |
| PKG-01 | P0 | 공개 API와 타입 호환 | 다중 export 및 패키지 소비 검사 구현 | ESM/CJS/선택 엔트리·fresh consumer 검사 통과 |
| RUN-01 | P0 | 여러 월드의 독립 수명 | `createGaesupRuntime`, Provider, 개별 store | 같은 ID를 써도 상태·입력·정책 응답이 다른 월드에 적용되지 않음 |
| RUN-02 | P0 | 종료 후 자원 회수 | 런타임·씬·환경 dispose 경로 | RAF/구독/타이머/소유 GPU 자원이 잔류하지 않음 |
| SAVE-01 | P0 | 검증된 저장과 복구 | SaveSystem, 도메인 바인딩, 진단·adapter | 손상·버전 불일치·부분 실패에서 기존 상태 보호 |

| MOVE-01 | P1 | 지형·가구를 반영한 이동 | NavigationSystem 및 미니룸 높이 sampler | 계단 도달, 절벽 거부, 장애물 편집 후 경로 갱신 |

| GPU-02 | P1 | 자연 환경과 후처리 | Grass, Water, WeatherEffect, Bloom | 지형 확장 후 버퍼 초과 0, 그림자·물·눈 표시 |
| NPC-01 | P1 | NPC 정책 요청 수명·격리 | scheduler/simulation/adapter registry | 취소·교체 후 오래된 응답 적용 0, 대량 NPC 비교 가능 |
| NET-01 | P1 | 네트워크와 서버 계약 | network adapters, visit, server contracts | 중복 명령·stale snapshot 처리, 재접속 결과 검증 |
| PLUG-01 | P1 | 플러그인 확장·의존성 관리 | PluginRegistry, ExtensionRegistry | 중복/순환/버전 오류 명확, 해제 시 다른 소유자 유지 |

## 5. 이번 미니홈피 제품 범위

### 5.1 탐색과 편집

- 기본 화면은 3D 공간 탐색이며 `?edit=1` 또는 공간 꾸미기 버튼으로 편집한다.
- 프로필, 홈/다이어리/방명록, 세 가지 테마, 아바타 스타일을 제공한다. 현재 기록의 저장 기반은 브라우저 로컬 데이터이며 계정 기반 원격 기록으로 표현하지 않는다.
- 초기 24×24 지형을 8칸씩 최대 64×64까지 확장한다. 잔디·눈·모래·바다·돌길·나무 타일, 1/3/5 브러시, 높이와 방향별 계단을 편집한다.
- 가구 12종, 최대 160개. 배치·선택·드래그·회전·복제·삭제·격자·스냅을 제공한다.
- 한 번의 브러시 드래그는 한 번의 실행 취소 단위다. 세션 이력은 50개까지 유지한다. Esc/포인터 취소는 미완료 편집을 취소한다.
- 카메라 시점, 직교/원근, 확대·회전·이동, 따라가기, 키보드·클릭 이동과 모바일 터치를 제공한다.

수용 기준: 높이·계단 편집→undo/redo→확장→저장→재접속에서 지형 좌표와 배치가 유지되어야 한다. 390px 폭에서 가로 넘침이 없어야 하며 주요 조작 버튼에 접근할 수 있어야 한다.

### 5.2 렌더링과 성능

- 잔디는 타일별 셀 배치와 인스턴싱을 사용하고, 큰 지형에서는 청크로 나눈다. 현재 환경 코드의 잔디 예산은 economy 80,000 / balanced 140,000 / high 240,000이다. 예산은 FPS 보장 수치가 아니다.
- 바다, 바람과 물결, 맑음/눈/눈보라, 주간/저녁, 발광 가구와 Bloom을 유지한다.
- 자연 애니메이션이 켜지면 연속 렌더가 필요하다. 애니메이션을 끄고 이동·보간·표시가 끝난 뒤에는 RAF가 멈춰야 하며 다음 조작 때 재개되어야 한다.
- 성능 패널은 전체/장면/그림자/기타 draw, 인스턴스, 삼각형, CPU 제출 시간, 자원 수를 표시한다. CPU 제출 시간을 GPU 실행 시간으로 표기하지 않는다.

수용 기준: 양 백엔드에서 지형 확장·날씨 전환·일시 정지 이후 GPU validation 및 shader 오류 0. 자연 효과를 끈 정지 상태에서 추가 렌더와 환경 시간이 증가하지 않아야 한다.

### 5.3 데이터 보존과 공유

- 저장 키 `gaesup.minihome.v1`과 백업 키를 유지한다. 기존 v1 데이터의 새 필드는 기본값으로 보완한다.
- 다른 탭 변경은 기대했던 원본 문자열과 비교해 충돌을 감지한다. 검증되지 않은 데이터를 정상 저장으로 덮어쓰지 않는다.
- JSON 백업/복원, 공유 링크, Unity 내보내기를 제공한다. 공유 링크는 24,000자 제한을 넘으면 파일 백업으로 안내한다.
- 방문 시 받아온 공유 월드와 개인 기록·로컬 공간의 복원 경계를 유지한다.

### 5.4 함께 방문하기

`scripts/minihome-room-service.mjs`는 SSE 연결과 HTTP 명령으로 방·참가자·위치·근거리 채팅·공간 공유를 처리한다. 첫 입장자의 편집 권한, 세션 토큰, 방 격리, 입력 크기/빈도를 검사한다. 개발/preview 서비스와 운영 서버는 별도다.

**GitHub Pages는 정적 호스팅이다.** 이번 Pages 배포 자체가 방 서버를 제공하지 않는다. 운영 함께 방문하기의 수용 조건은 별도 HTTPS 서버와 `VITE_MINIROOM_SERVER` 연결, 두 클라이언트 왕복 검증이다. 기능은 유지하고 이 서버 연결 상태를 배포 범위와 구분한다.

## 6. 성능 요구사항과 측정

상세 개선 항목 R01–R31과 기존 증거는 [런타임 성능 PRD](./PRD-runtime-performance.md)를 따른다. 이 문서는 제품 범위를 통합하며 기존 수치의 재측정을 가장하지 않는다.

| 측정 | 목표/판정 | 조건 |
| --- | --- | --- |
| 정합성 | GPU 오류·저장 손실·종료 후 상태 변경 0 | 기능과 성능 최적화 모두의 선행 조건 |
| 프레임 시간 | 목표 데스크톱 p95 ≤16.7ms, 모바일 p95 ≤33.3ms | 제품 목표; 실제 하드웨어별 기준선 수집 후 달성 판정 |
| 회귀 | 같은 시나리오 p95가 기준선보다 10% 이상 악화하면 조사 | renderer/DPR/장면/seed/워밍업 고정 |
| 유휴 작업 | 자연 효과 중지 후 불필요한 RAF 0 | 입력·카메라·이동이 끝난 상태 |
| 편집 | p95 명령 처리·저장·경로 재계산 시간 기록 | 24/32/64 지형 및 22/160 가구 비교 |
| 로드 | HTML/JS/asset bytes와 첫 3D 표시 시점 기록 | cold/warm 구분, 대형 chunk 경고 추적 |
| 수명 | 반복 mount/unmount 후 소유 구독·자원 잔류 0 | 공유 캐시와 월드별 자원 구분 |

수치에는 소스 commit/content hash, 브라우저·GPU·백엔드·DPR, 화면 크기, 장면 크기, 샘플 수, p50/p95/max와 오류를 같이 저장한다. 소프트웨어 렌더러의 기능 검사는 실제 GPU 성능 증거를 대신하지 않는다.

## 7. 확인된 간극과 우선순위

1. **P0 배포 분리:** 기존 release workflow는 npm 발행과 Pages 배포가 결합돼 있다. 미니홈피 소스 배포 전용 workflow로 npm 버전을 임의 발행하지 않고 현재 예제를 갱신한다.
2. **P0 잔디 버퍼 교체:** 이번 브라우저 검증에서 지형 확장 시 WebGPU 인스턴스 수와 이전 vertex buffer 크기의 불일치를 발견했다. 개수가 바뀌면 geometry를 교체하고 양 백엔드 회귀로 확인한다.
3. **P0 검증 경로:** 계단 단위 검사의 NavigationSystem 초기화 누락과 브라우저 검사의 가려진 타일 클릭을 수정한다. 테스트 통과를 위해 제품 기능을 제거하지 않는다.
4. **P1 운영 방문 서버:** 정적 사이트 공개와 운영 멀티플레이 서버 제공을 별도 마일스톤으로 관리한다.
5. **P1 성능 예산:** 설치 환경 검증과 지원 조합 전체 검증을 구분하고, 실제 모바일 GPU별 예산과 cold-load 기준선을 확정한다.
6. **P1 문서 정합성:** 기존 `minihome-town.md`의 고정 24×24·유휴 설명은 이번 높이/확장/자연 애니메이션 모델에 맞춘다.
7. **P2 패키지 확장:** Unity 실제 에디터 실행, 자산 생성 서비스, 네트워크 복구·권위 계약은 해당 환경에서 개별 수용 검증을 누적한다.

## 8. 배포와 완료 기준

배포 대상: <https://jigglypop.github.io/gaesup-world/>. `/engine/`와 `/performance/` 경로도 유지한다.

이번 소스 배포는 작업 트리의 고정 스냅샷을 원격 main에 올리고 Pages 전용 workflow를 수동 실행한다. Pages 환경의 허용 브랜치 정책을 따른다. 로컬 사용자의 main 작업 트리·스테이징 상태는 보존한다. `.github/workflows/minihome-pages.yml`에서 타입 검사, 미니홈피 단위/서버 검사, production build 후 Pages artifact를 배포한다. 이는 npm에 발행된 1.0.32 바이트와 동일하다는 주장이 아닌 **1.0.32 작업 소스 기반 예제 배포**다.

완료 판정:

- PRD와 코드 인벤토리 저장, 제품 범위·기능·성능·운영 경계 명시.
- 타입 검사, 변경 관련 회귀, 전체 Jest 결과 확인. skip은 별도 기록.
- 실제 production build에서 WebGPU 및 WebGL2 지형 편집·저장·모바일·날씨 검사.
- Pages workflow 성공 및 live `version.json.commit`과 배포 commit 일치.
- 공개 페이지에서 실제 3D 렌더, 지형 확장 저장/새로고침 복원, 모바일 화면 확인.
- 스크린샷·테스트 결과·배포 주소는 [배포 기록](./minihome-release-2026-09-22.md)에 남긴다.

## 9. 실행 순서

| 단계 | 산출물 | 종료 조건 |
| --- | --- | --- |
| A. 현재판 공개 | 이 PRD, 인벤토리, 미니홈피 배포와 증거 | 위 배포 완료 기준 |
| B. 성능 안정화 | R01–R31 우선순위별 비교, 장치별 예산 | 동일 기능을 유지하며 측정된 병목 감소 |
| C. 운영 방문 | HTTPS 방 서버, 연결·재접속 관측 | 실제 두 클라이언트·권한·방 격리 검증 |
| D. 확장 검증 | 지원 패키지 조합, Unity, 플러그인 소비 예제 | 각 소비 환경의 실제 실행 통과 |

일정은 고정 날짜보다 각 단계의 검증 결과로 확정한다. 현재 기능을 임의로 제외하거나 완료되지 않은 운영 기능을 완료로 표시하지 않는다.
